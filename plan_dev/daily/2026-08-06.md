## Objetivo del día

Desbloquear el provider VirtualBox, arrancar las topologías Vagrant y completar las pruebas SSH de D2.

## M1 — Reparar provider y completar D2

### Estado

`done`

### Diagnóstico

- kernel activo: `7.0.0-28-generic`;
- VirtualBox: `7.2.6r172322`;
- `vboxdrv` no está cargado/disponible;
- KVM está cargado;
- `/sbin/vboxconfig` requiere privilegios administrativos;
- el intento `sudo -n /sbin/vboxconfig` fue rechazado porque requiere contraseña.

El log `/var/log/vbox-setup.log` confirmó la causa: VirtualBox 7.2.6 no puede compilar `vboxdrv` para kernel 7.0 por símbolos movidos al namespace KVM. Los headers del kernel activo existen y Secure Boot está desactivado.

### Acción necesaria fuera del repositorio

Se descargó y verificó mediante el checksum oficial el paquete VirtualBox 7.2.14 para Ubuntu 24.04. Un administrador debe instalarlo:

```bash
sudo apt install ./deploy/.local/downloads/virtualbox-7.2.14/virtualbox-7.2_7.2.14-174565~Ubuntu~noble_amd64.deb
```

Luego se debe volver a verificar `VBoxManage --version`. Si el post-install no carga el módulo, ejecutar nuevamente `sudo /sbin/vboxconfig`. Si aparece un conflicto con KVM, se diagnosticará antes de iniciar las VM.

### Validación automática obligatoria al reanudar

- provider VirtualBox utilizable;
- `vagrant up` single y split;
- acceso SSH a cada VM;
- Debian 13 verificado dentro de las VM;
- inventories coherentes con las IP;
- `vagrant halt` sin errores.

### Condición de stop

No avanzar al rol `common` sin convergencia real de ambas topologías.
