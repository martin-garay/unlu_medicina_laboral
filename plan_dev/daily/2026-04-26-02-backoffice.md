## Decisiones base para este frente

- El backoffice se implementara con Laravel + Filament.
- Filament sera interfaz administrativa, no capa de reglas de negocio.
- La arquitectura objetivo sera:

```text
Filament
    ↓
Application Actions
    ↓
Domain Services / Domain Rules
    ↓
Models / Persistence / Events / Audit
```

- No usar `UseCase` como convencion para clases nuevas.
- Usar `Application Action`.
- Distinguir siempre:
  - Filament Action: boton/interaccion visual.
  - Application Action: accion de negocio reutilizable.
- No redisenar la relacion N a N aviso-certificado.
- No implementar State Machine por ahora.
- No implementar multi-tenancy ni separacion por sedes por ahora.
- No implementar permisos por campo/columna.
- No almacenar certificados medicos en rutas publicas.
- Las lecturas y descargas de certificados medicos deben quedar auditables en el diseno.
- Las reglas de negocio deben ser testeables sin depender de Filament.
