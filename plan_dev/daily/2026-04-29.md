- No implementar `I4`.

- No exponer `certificado_base64`, `payload_crudo` completo, metadata completa ni `storage_path` como link.
- Todo cambio documental debe validarse con `git diff --check`.
- Todo milestone cerrado con cambios debe quedar en commit chico.

## Decisiones operativas del backoffice local/desarrollo

- En entorno local/desarrollo, el rol `admin` debe tener acceso a todos los permisos definidos en `config/backoffice.php`.
- El seeder `BackofficeRolesAndPermissionsSeeder` debe seguir sincronizando el rol `admin` contra la lista completa de permisos disponibles.
- El usuario local de prueba debe quedar asociado al rol `admin` cuando `BACKOFFICE_LOCAL_ADMIN_ENABLED=true`.
- Acceso total por permisos no significa saltear restricciones funcionales del módulo.
- Si un Resource fue definido como read-only, `admin` puede acceder a la interfaz habilitada, pero no debe crear, editar, borrar ni ejecutar acciones que el módulo todavía no implementa.
- Las restricciones read-only se mantienen especialmente para módulos con datos sensibles o flujos aún no especificados.
