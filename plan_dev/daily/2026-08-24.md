## M4 — Deploy completo sin security/firewall

### Estado

`needs_review`

### Objetivo

Ejecutar `site.yml --check --diff` y luego `site.yml` sólo si el diff es
razonable. Con `security_enabled: false` y `firewall_enabled: false`, Ansible no
debe aplicar los roles `hardening` ni `firewall`, ni exigir `nftables.service`
en monitoreo.

### Nota operativa

Testing usa HTTPS para el checkout Git porque PC Uni no llega a GitHub por SSH
en puerto 22. Los playbooks no deben cargar `group_vars/all.yml` como
`vars_files`; eso pisa valores del inventory y puede cambiar el release o
habilitar `security/firewall` accidentalmente.

El check pre-commit de provisioning es `bin/check-deploy`.

### Validación automática obligatoria

```bash
ansible-playbook -i inventories/testing/hosts.yml site.yml --check --diff
ansible-playbook -i inventories/testing/hosts.yml site.yml
bin/check-deploy
```

### Stop

- Detener si el check intenta modificar SSH hardening, firewall o nftables.
- Detener si el deploy requiere secretos o credenciales no disponibles.
